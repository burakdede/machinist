# Neovim

[← back to README](../README.md)

The shared Neovim configuration lives in [`dotfiles/.config/nvim/`](../dotfiles/.config/nvim/)
and is symlinked into `~/.config/nvim` by the dotfiles step.

## Layout and lifecycle

| Area | File | Responsibility |
|---|---|---|
| Entry point | [`init.lua`](../dotfiles/.config/nvim/init.lua) | Bootstraps lazy.nvim and loads config |
| Options | [`options.lua`](../dotfiles/.config/nvim/lua/config/options.lua) | Editor options and provider settings |
| Keymaps | [`keymaps.lua`](../dotfiles/.config/nvim/lua/config/keymaps.lua) | Global and LSP mappings |
| Autocommands | [`autocmds.lua`](../dotfiles/.config/nvim/lua/config/autocmds.lua) | Buffer and editor events |
| Plugin specs | [`lua/plugins/`](../dotfiles/.config/nvim/lua/plugins/) | Plugins, dependencies, triggers, setup |
| Lockfile | [`lazy-lock.json`](../dotfiles/.config/nvim/lazy-lock.json) | Exact plugin commits |

[`init.lua`](../dotfiles/.config/nvim/init.lua) bootstraps lazy.nvim under
`stdpath("data")` and discovers every spec in `lua/plugins/`. Plugins are lazy
by default; startup plugins explicitly set `lazy = false`.

`lazy-lock.json` is generated by lazy.nvim. Update it through `:Lazy update` or
`:Lazy sync`, review the diff, and commit it with the spec change. Do not edit
the lockfile manually.

## Plugin stack

### UI — [`ui.lua`](../dotfiles/.config/nvim/lua/plugins/ui.lua)

- `Mofiqul/dracula.nvim` — colorscheme, loaded at startup
- `nvim-lualine/lualine.nvim` — statusline, loaded on `VeryLazy`
- `nvim-tree/nvim-web-devicons` — icon dependency

The colorscheme is shared with [WezTerm](terminal.md), bat, and delta.

### Tools — [`tools.lua`](../dotfiles/.config/nvim/lua/plugins/tools.lua)

- `christoomey/vim-tmux-navigator` — Neovim/tmux pane navigation
- `nvim-telescope/telescope.nvim` — files, grep, buffers, and history
- `nvim-neo-tree/neo-tree.nvim` — file tree
- `lewis6991/gitsigns.nvim` — Git signs and hunks
- `folke/which-key.nvim` — mapping discovery

Telescope and Neo-tree use `nvim-lua/plenary.nvim`; Neo-tree also uses
`MunifTanjim/nui.nvim` and `nvim-web-devicons`. There is no Comment.nvim;
Neovim provides `gc` and `gcc`.

### Language tooling — [`lsp.lua`](../dotfiles/.config/nvim/lua/plugins/lsp.lua)

- `mason.nvim` — installs language servers inside Neovim
- `mason-lspconfig.nvim` — maps lspconfig names to Mason packages and enables them
- `nvim-lspconfig` — server configurations
- `nvim-cmp` — completion
- `LuaSnip` and `friendly-snippets` — snippets
- `nvim-treesitter` on `main` — parsing, highlighting, folding, and indentation

Mason is the cross-platform installation boundary for LSP servers. LuaRocks is
disabled because no configured plugin requires it. Optional Node, Python, Perl,
and Ruby remote-plugin providers are disabled in
[`options.lua`](../dotfiles/.config/nvim/lua/config/options.lua).

## Change guide

| Change | Edit | Follow-up |
|---|---|---|
| Editor defaults | [`options.lua`](../dotfiles/.config/nvim/lua/config/options.lua) | Restart Neovim |
| Global or LSP mappings | [`keymaps.lua`](../dotfiles/.config/nvim/lua/config/keymaps.lua) | Restart Neovim |
| Autocommands | [`autocmds.lua`](../dotfiles/.config/nvim/lua/config/autocmds.lua) | Restart Neovim |
| Plugin spec or setup | Relevant file in [`lua/plugins/`](../dotfiles/.config/nvim/lua/plugins/) | `:Lazy sync` |
| LSP server | `servers` in [`lsp.lua`](../dotfiles/.config/nvim/lua/plugins/lsp.lua) | Restart; Mason installs it |
| Treesitter parser | `parsers` in [`lsp.lua`](../dotfiles/.config/nvim/lua/plugins/lsp.lua) | Restart or `:TSUpdate` |
| Colorscheme | [`ui.lua`](../dotfiles/.config/nvim/lua/plugins/ui.lua) and [`wezterm.lua`](../dotfiles/.config/wezterm/wezterm.lua) | Keep Dracula settings aligned |

Keep plugin-specific mappings in the plugin spec. Add the same LSP or parser to
the preload lists in [`mac/editor/editor.sh`](../mac/editor/editor.sh) and
[`linux/editor/editor.sh`](../linux/editor/editor.sh) if it must be installed
during bootstrap rather than on first use.

### Add or remove a plugin

Add the spec, including its dependencies and load trigger, then run:

```bash
nvim --headless "+Lazy! sync" +qa
```

Commit the spec and updated lockfile. To remove a plugin, remove its spec, run
`:Lazy sync`, then `:Lazy clean` if it is reported as unused. Use `:Lazy update`
for routine updates. `just update-editor` also runs `:TSUpdate` and
`:MasonUpdate`.

## LSP and Treesitter notes

The `servers` table uses current nvim-lspconfig names. Empty entries use server
defaults; `settings` contains local overrides such as `gopls` static analysis
and Rust Clippy checks.

Treesitter is on the incompatible `main` branch, so do not copy `master`-branch
configuration such as `ensure_installed`, `highlight.enable`, `indent`, or
`auto_install`. Parsers use `nvim-treesitter.install()` and highlighting starts
per buffer through `vim.treesitter.start()`. This requires Neovim >= 0.12 and
the package-managed `tree-sitter` CLI >= 0.26.1.

## Commands and diagnostics

| Task | Command |
|---|---|
| Plugin state | `:Lazy` |
| Sync specs and lockfile | `:Lazy sync` |
| Update plugin commits | `:Lazy update` |
| Mason packages | `:Mason` |
| Update Mason packages | `:MasonUpdate` |
| Treesitter health | `:checkhealth nvim-treesitter` |
| LSP health | `:checkhealth vim.lsp` |
| lazy.nvim health | `:checkhealth lazy` |
| Provider health | `:checkhealth vim.provider` |
| Startup profile | `nvim --startuptime /tmp/nvim-startup.log` |

Machine state is outside the repository:

- `~/.local/share/nvim/lazy/` — lazy.nvim and plugins
- `~/.local/share/nvim/mason/` — Mason packages and registry
- `~/.local/share/nvim/site/parser/` — Treesitter parsers

Prefer `:Lazy sync`, `:MasonUpdate`, or `:TSUpdate` over deleting caches.
